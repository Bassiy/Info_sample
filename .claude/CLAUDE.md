# Info プロジェクト

情報収集・議論・知識蓄積のためのプロジェクト。
そして、ユーザの第2の頭脳・記憶領域としてユーザをサポートすること。

## フォルダ構成

- `sources/` : 収集した情報の生データ
  - `tech/` : エンジニア系トレンド（日付.md）
  - `news/` : 政治・時事ニュース（日付.md）
  - `business/` : ビジネス・業界動向（日付.md）
- `knowledge/` : エンジニアとしての第2の頭脳。**技術・エンジニアリング概念専用**
  - `concepts/` : 個別の技術概念（1ファイル1概念）
  - `map/` : 概念をまたぐ「クロスドメインな繋がり・共通パターン・原則」を記録する場所（フラット構造、サブフォルダなし）
  - ※ 政治・経済ニュース・ビジネス動向など技術に直接関係しないものは保存しない。それらは `sources/` で管理する
- `note/` : 動的資料のリアルタイムメモ・持ち越し用一時置き場（YYYY-MM-DD.md、昇華後削除）

## スキルと書き込み先

| スキル | 書き込み先 |
|--------|-----------|
| `/note` | `note/YYYY-MM-DD.md` |
| `/gather` | `sources/{domain}/日付.md` |
| `/connect` | `knowledge/map/パターン名.md` |
| `/learn`, `/study` | `knowledge/concepts/` |

学習の定義・フローの詳細は `.claude/docs/learning.md` を参照。

## スキルスクリプトのルール

スキルが使用するスクリプトは `.claude/skills/{スキル名}/scripts/` に配置する。
フックスクリプトは `.claude/hooks/` に配置する。
詳細は `.claude/docs/skill-scripts.md` を参照。

## knowledge/ の運用ルール

- `concepts/` の概念定義が唯一の正解。`map/` では概念を再説明しない（参照のみ）
- 概念ファイルの命名：`{概念名}.md`（英語スネークケース。例: `tcp_ip.md`, `docker.md`）
- `map/` のファイル命名：パターン・原則名をケバブケース（例: `encapsulation-as-extension.md`）
- `map/` はフラット構造。ドメインごとのサブフォルダは作らない
- `map/` に書くのは「単体概念では表現できないクロスドメインな繋がり・パターン・原則」のみ。概念の再説明・一覧は書かない
- 理解が変わったときは新規ファイルを作らず既存ファイルを更新する
