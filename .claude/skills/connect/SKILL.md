概念間の「クロスドメインな繋がり・共通パターン・背後にある原則」を発見し、壁打ちで理解を深め、必要であれば `knowledge/map/` に記録する。

引数に「縦」「前提」「依存」などが含まれる場合は**縦モード**で動作する（後述）。
それ以外はデフォルトの**横モード**（クロスドメイン探索）で動作する。

2つのフェーズで動く：**発見** → **深化と判断**

---

## フェーズ1：発見

### ステップ1：起点概念の把握

引数に概念ファイル名が指定されていればそれを読む。なければ直近の会話で完成した概念を確認する。

概念ファイルを読み、以下を抽出する：
- この概念の**抽象的な構造・パターン**（例：「変換テーブル」「包んで拡張」「階層化」「問い合わせと応答」）
- 本文中で**言及されている他の概念名やキーワード**

### ステップ2：関連候補の検索

**2-1. キーワードgrepで明示的な関連を特定**

概念ファイルから主要キーワードを抽出し、`knowledge/concepts/` をgrepする：
```
grep -rl "キーワード" knowledge/concepts/
```

**2-2. ファイル名スキャンで暗黙の関連を追加**

```
ls knowledge/concepts/
```
ファイル名一覧を見て、抽象構造が似ていそうな候補をLLMが推論する。キーワードに引っかからない「暗黙のつながり」を拾うのが目的。

**2-3. 候補を精読（上限8件）**

**横モード（デフォルト）：** 候補ファイルを読み、クロスドメインなつながりがあるかを確認する。同一ドメイン内の隣接概念は候補から外す。

**縦モード：** 同一ドメイン内の制限を外す。「この概念を理解するために必要な前提概念」「この概念が依存している土台」という視点で探索する。

### ステップ3：繋がりの提示

1〜3件に絞り、以下を簡潔に伝える：

**横モード：**
- どのドメインをまたいでいるか
- どんな共通構造・パターンがあるか
- なぜこれが面白いと思ったか

**縦モード：**
- どの概念が土台・前提になっているか
- どういう依存関係でつながっているか
- どこまで遡ると理解が深まるか

ユーザーが「なるほど、見てみる」となれば次のフェーズへ。「あまり関係ない」であれば終了。

---

## フェーズ2：深化と判断

ユーザーの反応に応じて壁打ちを行い、理解を深める。

壁打ちの結論に応じて以下を判断する：

| 結論 | アクション |
|---|---|
| 複数概念にまたがる繋がり・パターンが確認できた | `knowledge/map/` に保存 |
| 実は単体概念として言語化すべきものだった | `/learn` を提案 |
| 既存の `concepts/` ファイルに追記すれば十分 | 直接編集を提案 |
| 縦の依存チェーンが確認できた | `concepts/` への「前提概念」追記 or `map/` 保存か、ユーザーに確認 |
| 繋がりが思ったより浅かった | 保存しない |

---

## mapファイルの保存

**保存先**：`knowledge/map/{パターン名}.md`（フラット構造、サブフォルダなし）

**ファイル名**：パターン・原則名をケバブケース（例：`encapsulation-as-extension.md`、`lookup-table-as-indirection.md`）

### テンプレート

```markdown
# {パターン・原則名}

## 捉えるもの
{このmapが捉えるつながり・パターンを1〜2文で}

## 関連概念
- [concept.md](../concepts/concept.md) — {ドメイン}

## 構造
{LLMが粒度を判断して自由に記述。大項目→中項目→小項目の階層で整理する}

## 図（任意）
{3概念以上が絡む場合や、視覚化で理解が深まる場合に作成}
{subgraph（クロスドメイン・集合感向き）またはmindmap（シンプルな接続向き）をLLMが使い分ける}
```
